# Interface polish — October 2026

The app keeps its paper, literary type and quiet instruments across these changes:

- Continue Reading resolves manga art through the shelf's disk cache, including a bounded source fetch when the selected series has no cached cover. Local manga still uses its local jacket.
- All document formats have previews. PDFs retain their first page; TXT, HTML, DOCX and ODT use a bounded excerpt of the converted document, rendered onto paper. Startup repairs missing previews without replacing reading progress or other metadata.
- Document chrome uses the book reader's continuous strip. Back, title, bookmark and Tools keep their positions; map and settings live in Tools. PDF viewing controls and progress have their own rows so the progress instrument has the full width.
- A whole-content rail replaces Android's browser scrollbar. Its extent comes from the book's complete chapter map rather than the changing loaded window. The lower instrument shows percentage and a concrete pages-left count in paged mode, or an explicitly estimated chapter reading time in continuous mode. Narrow layouts stack the chapter title and readout.
- Reader loading uses the destination's paper, margins and leading. PDF cover handoff waits for the visible page's rendered bitmap, as the text reader already waits for content paint. The Android shell waits for its saved appearance before mounting a destination, so the loading frame and arriving screen use the same animation family.
- Full, Minimal and Off are one glass-treatment choice backed by the existing preferences. Painted surfaces use a restrained ramp and one edge. Their opacity is calculated for the actual rendering path, preventing Minimal from receiving a thin glass fill without the diffusion that gives it body.
- Extension browsing, installation, source filters, repository fields, challenge prompts and downloads use Folio's typography and etched controls.
- Browse and Extensions now share More's section headings, grouped panels, icon tiles and divided rows through `FolioHub`. Source and extension catalogs keep lazy rows inside continuous panels. Catalog tabs use an underline; install, update, trust and retry actions stay quiet, with uninstall in a row menu. Narrow layouts and enlarged text move actions beneath the row text. Refresh and source preferences live in the existing options menu.
- Fresh installations start with Welcome, followed by appearance, Echoes models, narration models/voices, notifications and a final review. Downloads are explicit and optional. Setup owns the opening screen and mounts Home only after completion. Updates skip setup; interrupted first-install setup resumes. The late-bound navigation controller is observable, so Home renders on cold launch without a tab round trip.

`InterfacePolishRenderTest` renders light/dark treatments at 320dp with enlarged text and at 393dp. `DocumentImportTest` checks document previews, office conversion and repair during a concurrent progress update. Existing material-opacity and page-block regressions cover the shared rendering and progress primitives.

`MangaHubRenderTest` renders the shared More, Browse and Extensions components in light and dark themes at 320dp (1.4× text), 360dp and 393dp. The resulting 18 local previews are under `shared/build/visual-review/manga-hub`. That render check and all five `CoherentMaterialsTest` cases passed alongside Android release compilation for 1.2.120 (174). No device interaction was used for this catalog redesign.

The 1.2.121 refinement removes visible counts from the extension tabs, gives each label an equal slot, and uses a short centered selection underline. Large-text tabs can scroll rather than squeeze their labels. Home-screen widgets use modern color fields and clearer hierarchy; Audiobook adds a circular cover/progress display and the existing narration controls. See `widgets-and-notifications.md` for native render and playback-state checks.
